2. Infrastructure (Terraform)

What Terraform creates

infra/
├── main.tf              # VPC, subnets, IGW, route tables
├── security_groups.tf   # SG for ALB, ECS, RDS, Redis
├── alb.tf               # Application Load Balancer + target group
├── ecr.tf               # ECR repository (ivr-app)
├── ecs.tf               # ECS cluster, task definition (2 containers), service
├── rds.tf               # PostgreSQL (pgvector for RAG + checkpoints)
├── redis.tf             # ElastiCache Redis (session state)
├── iam.tf               # Execution role + task role
├── secrets.tf           # Secrets Manager secret shell
├── variables.tf         # All configurable variables
└── outputs.tf           # ALB URL, cluster name

Deploy infrastructure

# Initialize Terraform
cd infra
terraform init

# Preview changes
terraform plan -var="db_password=YOUR_STRONG_PASSWORD"

# Apply (creates all AWS resources)
terraform apply -var="db_password=YOUR_STRONG_PASSWORD"

# Save outputs
terraform output app_url    # → http://dev-ivr-alb-xxxx.us-east-1.elb.amazonaws.com
⚠ First-time deploy takes ~10 minutes — RDS and ElastiCache provisioning are the slowest steps. Subsequent applies are faster.

Build & push commands

# 1. Login to ECR
aws ecr get-login-password --region us-east-1 | \
  docker login --username AWS --password-stdin \
  348452968516.dkr.ecr.us-east-1.amazonaws.com

# 2. Build & push main app
docker build -t 348452968516.dkr.ecr.us-east-1.amazonaws.com/ivr-app:latest .
docker push 348452968516.dkr.ecr.us-east-1.amazonaws.com/ivr-app:latest

# 3. Build & push mock API sidecar
docker build -f Dockerfile.mock \
  -t 348452968516.dkr.ecr.us-east-1.amazonaws.com/ivr-app:mock-api .
docker push 348452968516.dkr.ecr.us-east-1.amazonaws.com/ivr-app:mock-api
Tip: The .dockerignore excludes venv/, .git/, infra/, and other large directories to keep the build context small (~12 KB vs ~940 MB).

5. ECS Deployment

Task definition (2 containers)

{
  "family": "dev-ivr",
  "cpu": "512",                          // 0.5 vCPU
  "memory": "1024",                      // 1 GB
  "containerDefinitions": [
    {
      "name": "dev-ivr",                 // Main app
      "image": "ECR/ivr-app:latest",
      "portMappings": [{"containerPort": 8000}],
      "environment": [
        {"name": "LLM_PROVIDER",        "value": "groq"},
        {"name": "GROQ_MODEL",          "value": "qwen/qwen3.8-27b"},
        {"name": "BEDROCK_MODEL",       "value": "amazon.nova-micro-v1:0"},
        {"name": "CNO_API_BASE_URL",    "value": "http://localhost:8001"}
      ],
      "secrets": [
        {"name": "GROQ_API_KEY",        "valueFrom": "secrets-arn:GROQ_API_KEY::"},
        {"name": "TWILIO_API_KEY",      "valueFrom": "secrets-arn:TWILIO_API_KEY::"},
        // ... 9 total secrets
      ]
    },
    {
      "name": "dev-mock-api",            // Sidecar — backend simulator
      "image": "ECR/ivr-app:mock-api",
      "portMappings": [{"containerPort": 8001}],
      "essential": true
    }
  ]
}
Sidecar pattern: Both containers share the same network namespace in Fargate. The main app reaches the mock API at http://localhost:8001 — no service discovery needed.

Deploy / redeploy

# Force new deployment (pulls latest image)
aws ecs update-service \
  --cluster ivr-cluster \
  --service dev-ivr-svc \
  --force-new-deployment \
  --region us-east-1

# Wait for deployment to stabilize
aws ecs wait services-stable \
  --cluster ivr-cluster \
  --services dev-ivr-svc \
  --region us-east-1

# Verify
aws ecs describe-services --cluster ivr-cluster --services dev-ivr-svc \
  --query "services[0].deployments[*].{status:status,running:runningCount,taskDef:taskDefinition}" \
  --output table

Update environment variables (no Docker rebuild)

To change LLM model, provider, or feature flags without rebuilding the Docker image:

# 1. Get current task definition
aws ecs describe-task-definition --task-definition dev-ivr --query taskDefinition > /tmp/taskdef.json

# 2. Edit environment variables in /tmp/taskdef.json
#    e.g., change LLM_PROVIDER from "groq" to "bedrock"

# 3. Register new revision (strip read-only fields first)
aws ecs register-task-definition --cli-input-json file:///tmp/taskdef.json

# 4. Deploy new revision
aws ecs update-service \
  --cluster ivr-cluster \
  --service dev-ivr-svc \
  --task-definition dev-ivr:NEW_REVISION \
  --force-new-deployment

6. LLM Provider Configuration

The app supports two LLM providers via the LLM_PROVIDER environment variable. Switch at runtime — no code changes needed.

Groq default

  • Model: qwen/qwen3.8-27b
  • Latency: 100–300ms
  • Cost: ~$0.05–0.20/M tokens
  • Config: LLM_PROVIDER=groq

Amazon Bedrock alternative

  • Model: amazon.nova-micro-v1:0
  • Latency: 200–400ms
  • Cost: $0.035/M input tokens
  • Config: LLM_PROVIDER=bedrock

Available Bedrock models (cheapest first)

Model IDInput CostOutput CostNotes
amazon.nova-micro-v1:0$0.035/M$0.14/MText-only, fastest Amazon model
amazon.nova-lite-v1:0$0.06/M$0.24/MMultimodal support
amazon.nova-pro-v1:0$0.80/M$3.20/MMost capable Amazon model
meta.llama3-3-70b-instruct-v1:0$0.72/M$0.72/MStrong open-source
us.anthropic.claude-3-haiku-20240307-v1:0$0.25/M$1.25/MClaude via cross-region inference
⚠ Bedrock model access must be enabled in the AWS Console.
Go to: AWS Console → Amazon Bedrock → Model access → Manage model access → enable the models you want. This cannot be done via CLI.

7. Twilio Setup

One-time Twilio Console setup

1
Create API Key
Twilio Console → Account → API Keys & Tokens → Create API Key (Standard)
Save Key SID as TWILIO_API_KEY and Secret as TWILIO_API_SECRET
2
Create TwiML App
Twilio Console → Voice → TwiML Apps → Create
Set Voice URL to: http://YOUR_ALB_URL/webhook/voice (POST)
Set Status Callback to: http://YOUR_ALB_URL/webhook/status (POST)
Save the TwiML App SID as TWILIO_TWIML_APP_SID
3
Add secrets to AWS
Add TWILIO_API_KEY, TWILIO_API_SECRET, TWILIO_TWIML_APP_SID to Secrets Manager (see Section 4)
4
Deploy ECS with new secrets
Force new deployment to pick up the secrets from Secrets Manager

How browser calls work

Browser (dashboard softphone)
    │
    ├─ GET /client/token  →  Twilio Access Token (JWT)
    │
    ├─ Twilio.Device(token).connect()  →  Twilio signaling servers
    │
    └─ Twilio servers POST /webhook/voice  →  ALB → ECS → TwiML response
       │
       └─ <Gather input="speech"> → caller speaks → POST /webhook/gather
          → LangGraph processes → TwiML response → loop

Workflow 1: CI (.github/workflows/ci.yml)

Runs on every push to master/staging and all pull requests.

StageJobWhat it doesNeeds API Keys?
1 Unit Tests Runs tests/test_utils.py with dummy API keys No (dummy keys)
2 Eval Tests Runs tests/eval_slots.py (no LLM) + tests/eval_intents.py (Groq LLM) GROQ_API_KEY only
3 E2E Twilio Runs tests/eval_e2e_twilio.py — master branch only All keys 
# .github/workflows/ci.yml (key sections)

name: CI
on:
  push:
    branches: [master, staging]
  pull_request:
    branches: [master]

jobs:
  unit-tests:                          # Stage 1 — no API keys
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11", cache: pip }
      - run: pip install -r requirements.txt
      - run: python tests/test_utils.py
        env:
          OPENAI_API_KEY: "sk-dummy"   # dummy — tests don't call APIs
          GROQ_API_KEY: "gsk-dummy"
          # ... other dummy keys

  eval-tests:                          # Stage 2 — intent eval needs Groq
    needs: unit-tests
    steps:
      - run: python tests/eval_intents.py
        env:
          GROQ_API_KEY: ${{ secrets.GROQ_API_KEY }}  # real key from GitHub Secrets

  e2e-tests:                           # Stage 3 — full E2E (master only)
    needs: eval-tests
    if: github.ref == 'refs/heads/master'
    steps:
      - run: python tests/eval_e2e_twilio.py
        env:
          GROQ_API_KEY: ${{ secrets.GROQ_API_KEY }}
          TWILIO_ACCOUNT_SID: ${{ secrets.TWILIO_ACCOUNT_SID }}
          # ... all real keys

Workflow 2: Deploy (.github/workflows/deploy.yml)

Triggers on push to master (auto-deploy to dev) or manual dispatch (dev/prod).

StageJobWhat it doesTrigger
1 Build & Push Docker build → tag with SHA → push to ECR (:latest + :sha-xxxx) Always
2 Deploy Dev ECS force-deploy → wait stable → health check (/health) Push to master / manual (dev)
3 E2E Test Dev Run E2E tests against deployed dev ALB After dev deploy (push only)
4 Deploy Prod ECS force-deploy → wait stable → health check Manual dispatch + approval gate 
# .github/workflows/deploy.yml (key sections)

name: Deploy
on:
  push:
    branches: [master]
  workflow_dispatch:
    inputs:
      environment:
        type: choice
        options: [dev, prod]

jobs:
  build:                                # Build Docker image → ECR
    runs-on: ubuntu-latest
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
      - uses: aws-actions/amazon-ecr-login@v2
      - run: |
          IMAGE_TAG="sha-$(git rev-parse --short HEAD)"
          docker build -t "${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}" .
          docker tag ... :latest
          docker push ...

  deploy-dev:                           # Auto-deploy to dev on push
    needs: build
    environment: dev
    steps:
      - run: |
          aws ecs update-service \
            --cluster ivr-cluster \
            --service dev-ivr-svc \
            --force-new-deployment
      - run: |
          aws ecs wait services-stable \
            --cluster ivr-cluster --services dev-ivr-svc
      - run: |                          # Health check with retry
          for i in $(seq 1 12); do
            STATUS=$(curl -s -o /dev/null -w "%{http_code}" "${DEV_URL}/health")
            [ "$STATUS" = "200" ] && exit 0
            sleep 5
          done; exit 1

  deploy-prod:                          # Manual trigger + approval gate
    needs: build
    environment: production             # GitHub environment with required reviewers
    if: github.event.inputs.environment == 'prod'
    steps:
      - run: aws ecs update-service --cluster ivr-cluster --service prod-ivr-svc ...

11. Monitoring & Troubleshooting

CloudWatch logs

# View recent logs
aws logs tail /ecs/dev-ivr --follow --since 5m --region us-east-1

# Search for errors
aws logs filter-log-events \
  --log-group-name /ecs/dev-ivr \
  --filter-pattern "ERROR" \
  --start-time $(date -d '1 hour ago' +%s000) \
  --region us-east-1

ECS service health

# Check service status
aws ecs describe-services --cluster ivr-cluster --services dev-ivr-svc \
  --query "services[0].{status:status,running:runningCount,desired:desiredCount,deployments:deployments[*].{status:status,running:runningCount,taskDef:taskDefinition}}" \
  --output table

# Check task health
aws ecs list-tasks --cluster ivr-cluster --service-name dev-ivr-svc
aws ecs describe-tasks --cluster ivr-cluster --tasks TASK_ARN \
  --query "tasks[0].containers[*].{name:name,status:lastStatus,health:healthStatus,exit:exitCode}"

Common issues

SymptomCauseFix
Task keeps restarting Missing secrets or env vars Check CloudWatch logs for startup errors. Verify all 9 secrets are in Secrets Manager.
502 Bad Gateway from ALB Task not healthy / still starting Wait 60s for task to register with target group. Check security group allows ALB → ECS on port 8000.
All intents route to "escalate" LLM API key invalid or model deprecated Check GROQ_API_KEY in Secrets Manager. Verify model name is valid on Groq.
Softphone "AcquisitionFailedError" Browser blocks mic on HTTP Use HTTPS, localhost, or Chrome insecure origin flag (Section 8)
Softphone "application error 31480" TwiML App voice URL misconfigured Set TwiML App voice URL to http://ALB_URL/webhook/voice
Bedrock "Operation not allowed" Model access not enabled AWS Console → Bedrock → Model access → enable the model
Mock API connection refused Sidecar container crashed Check mock-api stream in CloudWatch logs
