#1

Network Architecture

From public-only subnets to a production-grade VPC topology

Current State

  • VPC with 2 public subnets only (map_public_ip_on_launch = true)
  • Fargate tasks run in public subnets with assign_public_ip = true
  • No NAT Gateway — containers reach the internet via their own public IPs
  • RDS and Redis sit in the same public subnets (though not publicly accessible)
  • No VPC endpoints — all AWS API calls traverse the public internet

Improvement

  • Add private subnets (2 AZs) for ECS tasks, RDS, and Redis
  • Deploy NAT Gateway in each public subnet for outbound internet access
  • Add VPC endpoints for ECR (dkr + api), S3, Secrets Manager, CloudWatch Logs
  • Move all backend resources (ECS, RDS, Redis) to private subnets — only ALB stays public

Why It Matters

  • Containers with public IPs are directly addressable from the internet — attack surface reduction
  • VPC endpoints eliminate data transfer charges for ECR image pulls and log shipping
  • Required for compliance frameworks (PCI DSS, HIPAA) that mandate network segmentation

How to Implement

  • Add aws_subnet.private (2 AZs), aws_nat_gateway, aws_eip, private route tables
  • Add aws_vpc_endpoint for ECR, S3, Secrets Manager, CloudWatch
  • Update ECS service: assign_public_ip = false, subnets = private
  • Move RDS/Redis subnet groups to private subnets

Effort ~2 days Terraform changes | NAT Gateway cost: ~$32/mo per AZ ($64/mo for 2 AZs)

#2

HTTPS & TLS

From HTTP-only to fully encrypted traffic

Current State

  • ALB listener on port 80 (HTTP only) — no HTTPS listener
  • ALB SG only allows inbound port 80
  • No ACM certificate, no custom domain, no Route 53
  • Twilio webhooks use http:// — browser mic access blocked (requires HTTPS)
  • WebSocket connections use ws:// instead of wss://

Improvement

  • Request ACM certificate for custom domain (e.g., ivr.uic-insurance.com)
  • Add HTTPS listener (443) on ALB with ACM cert
  • Redirect HTTP (80) to HTTPS (443) automatically
  • Configure Route 53 hosted zone with A record alias to ALB
  • Update Twilio webhook URLs to https:// and WebSocket to wss://

Why It Matters

  • Browser microphone access requires HTTPS — the softphone web UI is broken without it
  • Twilio strongly recommends HTTPS for all webhook endpoints
  • PII (phone numbers, DOB, policy numbers) transmitted in plaintext over HTTP

How to Implement

  • Add aws_acm_certificate + DNS validation via Route 53
  • Add aws_lb_listener.https (443) with certificate, modify HTTP listener to redirect
  • Update ALB SG to allow inbound 443
  • Add aws_route53_zone and aws_route53_record (A alias)

Effort ~1 day | ACM certs are free | Route 53: $0.50/mo per hosted zone + $12/yr domain

#3

High Availability & DR

From single points of failure to multi-AZ resilience

Current State

  • ECS service desired_count = 1 — single task, single AZ effectively
  • RDS: single instance, multi_az = false (default), skip_final_snapshot = true
  • Redis: single-node ElastiCache cluster (num_cache_nodes = 1), no replication
  • Health check is basic /health endpoint — does not verify database or Redis connectivity

Improvement

  • Set ECS min_tasks = 2 across different AZs for zero-downtime deployments
  • Enable RDS Multi-AZ (multi_az = true) for automatic failover
  • Switch to ElastiCache Replication Group with 1 primary + 1 replica across AZs
  • Implement deep health checks that verify DB, Redis, and LLM API connectivity
  • Add circuit breakers for external services (Deepgram, ElevenLabs, Groq)
  • Enable RDS automated backups with 7-day retention and final snapshot on delete

Why It Matters

  • Single ECS task = any deployment or crash drops 100% of active calls
  • Single-AZ RDS = full outage if that AZ has issues (happens multiple times/year)
  • Insurance call centers cannot tolerate downtime during business hours

How to Implement

  • Update var.min_tasks default to 2, set deployment minimum_healthy_percent = 100
  • Add multi_az = true to aws_db_instance, set skip_final_snapshot = false
  • Replace aws_elasticache_cluster with aws_elasticache_replication_group
  • Extend /health to query DB and Redis, return degraded status if either fails

Effort ~3 days | Multi-AZ RDS doubles cost (~$28/mo more for t4g.small) | Redis replica: ~$13/mo

#4

Database Improvements

From bare-minimum RDS to production-grade data layer

Current State

  • Single RDS instance (db.t4g.micro), 20GB gp3, no replicas
  • Dev and prod share the same instance (different database names: ivr_dev, ivr_prod)
  • pgvector runs on the same instance — embedding queries compete with transactional writes
  • No connection pooling — each ECS task opens direct connections
  • No schema versioning tool — manual SQL migrations
  • deletion_protection = false, no automated backup retention configured

Improvement

  • Separate dev and prod into different RDS instances
  • Add a read replica for pgvector queries (RAG retrieval) to offload the primary
  • Deploy RDS Proxy for connection pooling and failover acceleration
  • Enable deletion_protection = true and automated backups (7-day retention)
  • Adopt Alembic for schema version control — migrations in source control
  • Enable Performance Insights for query-level monitoring

Why It Matters

  • Shared instance means a dev mistake (e.g., DROP TABLE) can impact prod
  • pgvector similarity searches are CPU-intensive — they degrade checkpoint writes under load
  • Without connection pooling, scaling ECS tasks exhausts the 80-connection limit on t4g.micro

How to Implement

  • Parameterize RDS per environment in Terraform (use workspaces or separate tfvars)
  • Add aws_db_instance read replica, point RAG retrieval to replica endpoint
  • Add aws_db_proxy resource, update ECS DATABASE_URL to proxy endpoint
  • Add Alembic to the Python project: alembic init, create initial migration from existing schema

Effort ~4 days | RDS Proxy: ~$20/mo | Read replica: ~$14/mo (t4g.micro)

#5

LLM Provider Resilience

From manual failover to automatic multi-provider resilience

Current State

  • Groq is the primary LLM provider; Bedrock is available but requires manual switch via LLM_PROVIDER env var
  • If Groq goes down, calls fail until an operator redeploys with LLM_PROVIDER=bedrock
  • No response caching — identical FAQ questions call the LLM every time
  • No token usage monitoring or budget alerts

Improvement

  • Implement automatic failover chain: Groq (primary) -> Bedrock (secondary) -> OpenAI (tertiary)
  • Add circuit breaker pattern: after N consecutive failures or latency > threshold, switch provider
  • Cache LLM responses for common FAQ/RAG queries in Redis (TTL 1 hour)
  • Track token usage per provider per day, alert when approaching budget thresholds
  • Add latency-based routing: if Groq response > 500ms, prefer Bedrock for next request

Why It Matters

  • Groq has had multiple outages (rate limits, capacity issues) — each one is a full IVR outage today
  • Response caching can eliminate 30-40% of LLM calls for common questions, saving both latency and cost
  • Insurance regulators expect documented uptime SLAs — manual failover does not meet those standards

How to Implement

  • Create an LLMProviderManager class with ordered provider list and circuit breaker state
  • Use tenacity library for retry logic with exponential backoff
  • Add Redis cache layer: hash prompt -> cached response (skip for PII/account-specific queries)
  • Emit custom CloudWatch metrics: llm_latency_ms, llm_failures, llm_tokens_used

Effort ~3 days application code | No additional infra cost

#6

Observability & Monitoring

From basic logs to full-stack observability

Current State

  • CloudWatch Logs with 7-day retention — standard ECS log driver
  • SSE-based log viewer in the web UI for real-time debugging
  • No custom metrics, no alarms, no dashboards
  • No distributed tracing — hard to debug latency across STT -> LLM -> TTS pipeline
  • No alerting — failures discovered manually

Improvement

  • Publish custom CloudWatch metrics: calls/min, avg response latency, auth success rate, LLM latency by provider
  • Enable AWS X-Ray tracing across the full call pipeline (STT -> LangGraph -> TTS)
  • Create CloudWatch alarms: error rate > 5%, p99 latency > 3s, ECS task count = 0, RDS CPU > 80%
  • Set up SNS topic for alarm notifications (email, PagerDuty, Slack webhook)
  • Build a CloudWatch dashboard: active calls, latency percentiles, error rates, LLM provider status
  • Increase log retention to 30 days (prod), add structured JSON logging

Why It Matters

  • Without metrics, you cannot measure SLA compliance or identify degradation trends
  • Voice latency issues need trace-level debugging — "which component added 800ms?"
  • Proactive alerting is the difference between "we noticed before callers did" and incident escalation

How to Implement

  • Add aws-embedded-metrics Python library for custom metric emission
  • Add aws-xray-sdk and patch HTTP clients, add X-Ray daemon as ECS sidecar
  • Define aws_cloudwatch_metric_alarm resources in Terraform
  • Add aws_sns_topic + aws_sns_topic_subscription for alert routing

Effort ~3 days | CloudWatch custom metrics: ~$0.30/metric/mo | X-Ray: ~$5/mo at moderate volume

#7

Security Hardening

From basic security to compliance-ready posture

Current State

  • Security groups: ALB allows 0.0.0.0/0 on port 80, app SG allows ALB only, RDS/Redis allow app SG only
  • Secrets Manager stores all API keys (Twilio, Groq, Deepgram, ElevenLabs, OpenAI)
  • Twilio webhook signature validation implemented in application code
  • No WAF, no DDoS protection, no VPC Flow Logs, no audit trail
  • No secrets rotation policy

Improvement

  • Deploy AWS WAF on ALB: rate limiting (100 req/s per IP), SQL injection rules, geo-blocking
  • Enable AWS Shield Standard (free) for DDoS protection on ALB
  • Enable VPC Flow Logs to S3 for network forensics
  • Enable GuardDuty for threat detection (anomalous API calls, compromised credentials)
  • Enable CloudTrail for full API audit logging
  • Configure secrets rotation via Lambda for Twilio and database credentials
  • Implement IAM least-privilege: scope ECS task role to only required Bedrock models and Secrets Manager ARNs
  • Plan for PCI DSS (payment card data) and HIPAA (health insurance data) compliance audits

Why It Matters

  • Insurance IVR handles PII (SSN, DOB, policy numbers) and PHI (health claims) — breach = regulatory fines
  • Without WAF, the ALB is exposed to bot traffic, credential stuffing, and application-layer DDoS
  • Compliance auditors require audit trails, encryption evidence, and access control documentation

How to Implement

  • Add aws_wafv2_web_acl with managed rule groups (AWSManagedRulesCommonRuleSet, RateBased)
  • Add aws_flow_log resource targeting VPC, destination S3 bucket
  • Enable GuardDuty and CloudTrail via Terraform (aws_guardduty_detector, aws_cloudtrail)
  • Create Lambda rotation functions for Secrets Manager

Effort ~5 days | WAF: ~$5/mo + $0.60/M requests | GuardDuty: ~$4/mo | CloudTrail: ~$2/mo

#8

Cost Optimization

From fixed-cost resources to right-sized, tagged infrastructure

Current State

  • All resources run on-demand pricing — no Savings Plans or Reserved Instances
  • ECS auto-scaling configured but desired_count = 1 with no scale-to-zero
  • No cost allocation tags — cannot attribute spend to dev vs prod
  • No AWS Budgets or billing alarms
  • NAT Gateway not used (because no private subnets) — will become a cost factor when added

Improvement

  • Use Fargate Spot for dev/staging environments (up to 70% savings)
  • Evaluate Compute Savings Plans for prod (up to 50% savings on Fargate)
  • Apply RDS Reserved Instances for prod (1-year, no upfront = ~35% savings)
  • Add cost allocation tags (Environment, Project, CostCenter) to all resources
  • Set up AWS Budgets with monthly threshold alerts ($100 dev, $500 prod)
  • Implement ECS scheduled scaling: scale down to 1 task outside business hours (6pm-8am)
  • Use S3 Intelligent-Tiering for VPC Flow Logs and CloudTrail storage

Why It Matters

  • On-demand pricing is 2-3x more expensive than committed pricing for predictable workloads
  • Without tags, finance cannot attribute cloud spend to the IVR project vs other workloads
  • Surprise bills erode stakeholder confidence in the cloud migration

How to Implement

  • Add capacity_provider_strategy block to ECS service with FARGATE_SPOT for dev
  • Purchase Savings Plans via AWS Console (requires billing access)
  • Add default_tags block in Terraform provider "aws" configuration
  • Add aws_budgets_budget resources with SNS notification actions

Effort ~2 days | Net savings: 30-50% on compute and database costs
