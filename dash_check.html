Session 1 — Entry Point & Request Lifecycle

How a phone call becomes an LLM response: run.py → main.py → webhooks/twilio_voice.py

run.py — three jobs before server starts

  • Tee stdout/stderr — wraps sys.stdout with _Tee so every print/log line goes to terminal + ivr.log + in-memory log_bus (powers SSE live viewer)
  • Windows event loop policy — must be set before uvicorn creates the loop
  • uvicorn.run("main:app", port=8888) — starts the FastAPI server
class _Tee: def write(self, msg): self._s.write(msg) # → terminal self._f.write(msg) # → ivr.log file from log_bus import push push(line) # → SSE /client/logs/stream

main.py — FastAPI app wiring

  • Routers: voice_router (/webhook/*), browser_router (/client/*), chat_router (/chat/*), dashboard_router (/dashboard/*)
  • structlog writes to sys.stdout → captured by _Tee above
  • CORS middleware: allow_origins=["*"] for dev

webhooks/twilio_voice.py — the IVR loop

POST /webhook/voice → greet caller, start <Gather> POST /webhook/gather (each caller utterance): 1. SpeechResult="" ? → re-prompt "I didn't catch that" 2. cno_graph.ainvoke({messages:[HumanMessage(transcript)]}, thread_id=call_sid) 3. result.transfer_to set? → <Say> + <Dial> 4. current_node=="goodbye"? → <Say> + <Hangup/> 5. else → <Say tts_text> + <Gather> (loop)

Key: thread_id = call_sid — each call has its own MemorySaver checkpoint. Two concurrent calls never share state.

graph.py — routing logic

def _route_after_auth(state): if auth_step == "complete": intent = state.get("current_intent") if intent in ("auth", ""): return END # no pre-auth intent return "router" # re-route immediately if auth_step == "failed": return "escalation" return END # mid-auth, wait for next turn

If caller says "check policy status" before auth, that intent is captured. Auth runs. On completion, graph immediately routes to policy — no extra round-trip.

Session 3 — Router Node

core/graph/nodes/router.py

Three-phase classification

1. ESCALATION CHECK (keyword scan — no LLM cost) "agent", "representative", "human", "transfer" → intent = "escalate" 2. FLOW LOCK CHECK active_flow="auth"|"otp" → mode="locked" → force back to active flow active_flow="contact" etc → mode="escalate_only" → LLM but can only escalate active_flow="" → mode="open" → full free routing 3. LLM CLASSIFICATION (Groq llama-3.3-70b, temp=0) → one word from VALID_INTENTS → unknown → "faq"

Context-switch modes

ModeWhenBehaviour
lockedauth, otpNo LLM. Forces back to active flow. Only escalation exits.
escalate_onlycontact, document, etc.LLM runs. Non-escalation intent overridden back to active flow.
openactive_flow=""Full free routing. Caller can pivot to any intent.

Session 5 — Service Nodes

core/graph/nodes/ — policy, payment, loan, beneficiary, contact, document, privacy, faq, escalation, goodbye

One-shot nodes (policy, payment, loan, beneficiary)

  • Called once, fetch data from CNO API, use LLM to format natural response
  • Return active_flow="" so router is free next turn
  • payment.py appends mandatory disclosure: "Please allow 24-48 hours for payment to post..."

Multi-step flows (contact, document)

  • Use otp_data dict to track sub-steps: contact_step, new_address, new_phone etc.
  • Return active_flow="contact" to lock router until complete or cancelled
  • Cancel detection at every step: "no", "cancel", "never mind", "don't want" → _exit_response()
  • contact.py uses word-boundary regex r'(address|street|zip)' so "I don't want to update the contact address" doesn't trigger collecting_address

Termination nodes

  • escalation — sets transfer_to=agent_phone. twilio_voice.py sees transfer_to → <Dial>
  • goodbye — twilio_voice.py sees current_node=="goodbye" → <Say> + <Hangup/>

Session 6 — Infrastructure

log_bus.py · services/session.py · services/conversation_store.py

Live log pipeline

structlog.info() → sys.stdout → _Tee.write() ├── sys.__stdout__ (terminal) ├── ivr.log file (disk) └── log_bus.push() ├── _buffer deque(maxlen=500) (history for new SSE clients) └── _queues list (asyncio.Queue per active SSE connection) └── GET /client/logs/stream → EventSource → Live Logs tab

conversation_store.py

  • In-memory dict for call history (_calls) and webchat sessions (_chats)
  • start_call(sid, from) / add_call_turn(sid, role, text, intent, node) / end_call(sid)
  • ensure_chat(sid) / add_chat_turn(sid, role, text) / get_chats() / get_calls()
  • Resets on server restart (no persistence — use for monitoring only)

WebChat API (webhooks/chat.py)

  • POST /chat/message — same LangGraph, thread_id="chat_{session_id}"
  • GET /chat/history/{sid} — returns full turn list
  • GET /chat/sessions — list all active sessions
  • POST /chat/reset/{sid} — clear session + LangGraph checkpoint
